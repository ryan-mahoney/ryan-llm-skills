# Claude Code Global Instructions

## External Rules Source
This machine keeps canonical agent rules in `~/.agents/rules/`.

When starting work:
1. Treat files in `~/.agents/rules/` as active global guidance.
2. Prefer these rules when they add constraints or style guidance.
3. If a repository has local instructions, merge them with these global rules.
4. If instructions conflict, follow this precedence:
   - system/developer instructions
   - repository-local instructions (e.g. `AGENTS.md`)
   - `~/.agents/rules/*`

## Design Rule Application Policy
The design/copy files are advisory design guidance. Engineering, testing, and verification
guides apply to their named tasks, including backend work; repository requirements prevail.

Apply the design/copy guides in `~/.agents/rules/` by default when work includes:
- UI layout, interaction patterns, components, or visual styling
- UX writing, labels, CTA/button text, form content, and table presentation
- Design system or frontend implementation decisions

Do not force design/copy guidance when work is primarily:
- backend logic, infrastructure, build tooling, tests, or data migrations
- API correctness, security, or performance work with no user-facing design/copy impact

If a rule would reduce correctness, accessibility, security, or maintainability, prioritize those qualities and treat the design rule as advisory.

When multiple rules apply:
1. Use the most specific rule for the element (e.g. CTA guide for buttons, form guide for forms).
2. Use broader documents (e.g. `functionalist-design.md`) as tie-breakers.
3. If still ambiguous, choose the option that is most predictable and easiest for users to complete tasks.

## Verification and Review
When implementing, running checks, addressing review findings, or publishing a PR, load
`~/.agents/rules/verification-and-review.md`. Apply its CI-owned broad testing policy and
explicit Jev verification and review-triage checkpoints. Without CI, broad testing stays
operator-managed outside agent evidence and does not block completion. Preserve acceptance
and known-failure obligations; CI results belong to the operator after publication, and publication needs authority.

## Portable Paths
When writing skills, templates, specs, documentation, or generated reports, load
`~/.agents/rules/portable-paths.md`. Keep saved paths relative to a declared base
and resolve machine-specific absolute paths only where consumers require them.

## Spec Artifacts
Spec artifacts live only in the adjacent workspace, at the location the spec-location
resolver returns (`node ~/.agents/scripts/spec-location/cli.mjs`). Never create or write
`.specs/` inside any checkout. If the resolver refuses, stop and report its remedy.
See `~/.agents/skills/spec-end-to-end/references/spec-location.md`.

## Engineering Writing
When writing PRs, commit messages, work tours, proposals, critiques, or specs, load
`~/.agents/rules/engineering-writing.md` and apply the relevant audience guidance.
Keep human-facing summaries concise and preserve useful detail in agent-facing specs.

## PR and Ticket Writing
When drafting or editing PR titles/descriptions or Jira/GitHub tickets, load and apply
`~/.agents/rules/pr-and-ticket-writing.md`, including its acceptance-criteria guidance.
This applies to backend and infrastructure work as well as user-facing changes; the design-only exclusions above do not apply to this writing guidance.

## Symlinked Rules Mirror
A mirrored rules folder exists at `~/.claude/rules/` and should contain symlinks to `~/.agents/rules/*`.
Always resolve symlinks and read the source files.

## Sync Command
If instructions or rules are added or changed, run:

```bash
~/.agents/sync.sh
```

This copies `~/.agents/claude/CLAUDE.md` to `~/.claude/CLAUDE.md` and refreshes rule symlinks.

## Attribution Policy
Never attribute work to Claude in repository artifacts.

For any PR, commit message, or review/discussion comment:
- Do not mention Claude, Claude Code, Anthropic, or "AI assistant" authorship.
- Do not add signatures or footers such as "Generated by Claude" or "Co-Authored-By: Claude".
- Write in a neutral teammate voice with no model/tool self-reference.
