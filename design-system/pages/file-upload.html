Design system

File upload

Upload text into a document with clear scope, format limits, and feedback. The local demo only reads selected files in the browser; it does not save or transmit them.

A writer brings an outside document into a project by uploading it. Restory reads the text, saves it as an ordinary Markdown file, and discards the original binary. Before saving, the writer chooses where the file is visible. See the upload control examples in context.

Text in, binary gone

Ingestion produces text. The uploaded file is transient: it is read once to create Markdown content, then dropped. This pass accepts plain text and Markdown; PDF is recognized but not yet extracted.

Adding a file

Adding a file offers two paths from one place: author a new file, or upload one. The control is a verb + noun button in a file list and a compact icon button inside the assistant composer. Icon-only controls carry an accessible name.

Visibility scope

Before a file is saved, the writer chooses who can see it. Scope is a single, mutually exclusive choice; the default is this section. Widening is always deliberate.

Org-wide is consequential

Promoting a file to organization scope exposes its content to everyone in the org. The dialog names that audience and the confirm repeats the outcome: “Share org-wide.”

Scope on a file

A file carries its scope wherever it is listed, so a writer can tell at a glance whether it is local to the section or shared more widely. Each pill carries a text label; organization scope has a distinct cross-document treatment.

Formats & limits

Accepted formats are explicit and enforced. Unsupported or oversized files are rejected in place. The message says what is wrong and how to recover; no empty file is created.

Rejected uploads

Upload feedback

Rejected uploads show a dismissible inline alert. A successful upload marks the new file with a New badge and a one-shot row highlight so the writer can find it without a blocking message.
