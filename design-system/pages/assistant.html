Design system

Assistant

A turn is an ordered stream of messages and states. The catalog keeps narrative primary, reasoning and tools subordinate, and makes streaming, failure, and user choice visible.

A turn is not one block of text. It is an ordered stream of typed messages — narrative, reasoning, tool activity, status, errors, usage — that arrive interleaved and update live. This page catalogs every message type and state, mapped to the AG-UI event that drives it.

Three rules hold throughout: every message has more than one state; streaming is the default, not the exception; hierarchy is functional — narrative is primary, reasoning and tools sit subordinate. Human and assistant turns are told apart by container, not by avatars.

Tool activity

§4.1Work Many tool calls collapse into one rail, not a stack of cards. While the run works, the rail shows the live call, verb, target, and running count. Once settled it states how many ran and whether any failed. A run-halting failure turns the line red; outcome reads by icon and text, never color alone.

Failures are never silently green

The rail counts failures and states them — “· N failed” — and a run-halting failure stops the line in a reserved red state.
