Accessibility

  • Each card is tabindex=0 with aria-roledescription="Draggable card" and an aria-label of its title plus its current column, so a screen reader hears both the section and the status it now holds.
  • Each lane is a labelled region whose name includes the column label and the live card count, so moving a card announces both the source and target lane.
  • The count badge is a JetBrains Mono number, kept tabular so the per-lane tally stays scannable as cards move.
  • Keyboard move is the accessible equal of drag: arrow keys change a card’s column (status) or rank without a pointer.
  • The kebab pinned to each card’s top-right corner is always visible and opens the section action menu, documented on the Drawers & Overlays page.

Keyboard

keyboard model

KeyAction
Arrow Left / RightMove the focused card to the previous or next column, changing its status.
Arrow Up / DownReorder the focused card up or down within its column.

Key handling is suppressed while focus is in an input, textarea, or contentEditable, so editing prose never moves a card.

Responsive

  • Lanes lay out horizontally; horizontal scroll is contained to the board, not the page.
  • Lanes keep a minimum width and never collapse to a single column on mobile, so the status columns stay legible.
  • The topbar and hintline wrap when space runs out.
  • No fixed-pixel widths force body-level horizontal overflow at 320px.
