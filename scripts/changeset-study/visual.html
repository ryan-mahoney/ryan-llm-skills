01 / The mechanism

Reason at the decision boundaries.

Read relevant source to settle the change. Compile exact operations where possible; use a single model request where local implementation is still needed. Keep updates in a staged workspace so later operations see current contents.

Exact operations first

Create, replace, rename, delete or update JSON. The runtime checks anchors and ownership without another model conversation.

Order shared-file changes

Dependencies and overlapping reads/writes serialize conflicts. Later operations see staged updates; stale anchors fail explicitly.

Repair at the batch boundary

The prototype permits one repair by default. Failed operations block dependents; successful draft work can carry into repair.

Source reading and behavioral checks still matter. A syntax pass cannot establish the intended impact. Disk publication requires exclusive writer ownership; the prototype is not crash-atomic.

02 / The measured result

Fewer round trips. Less repeated context.

Sol’s changeset arm used only one separate model-editor call across 16 trials. Most plans already contained the exact edits. That supports capable planning and deterministic application; this result does not establish a gain from cheaper editor routing.

1.32×

Task-balanced speed ratio for Sol; 95% interval 1.17–1.52×.
Bootstrap resamples eight workload families. This differs from the ratio of overall means. A small purposive corpus does not establish general production superiority.

Sol retained acceptance. Both approaches passed 16/16 before and after the supplemental audit.

DeepSeek and Mercury regressed. Changesets passed 13/16 and 8/16 respectively after the audit. Faster successful runs do not establish an overall advantage.

The original grader missed a contract. Supplemental checks found six additional regressions. These checks were post-hoc; candidates were never repaired using those results.

Read study design and limits

Six synthetic tasks and two historical fixes in extracted modules; three models, two approaches, two repetitions. Each pair used the same model and reasoning selector for all roles. The baseline used native Pi read/bash/edit/write tools with ordinary batching and parallel execution.

Selectors: deepseek/deepseek-flash:off, openai-codex/gpt-6.1-sol:low, openrouter/inception/mercury-2.5:low.

Code, prompts, workload and SDK were frozen. Pair order was balanced and randomized. Each cell had a 300-second / 32-call cap. Failures remain in results; failure-adjusted timing assigns the 300-second cap to unsuccessful cells.

This does not measure large feature delivery, full repository navigation, mixed-model routing, subscription quota, or the current managed owner/editor workflow. Provider load and caching can affect latency.

03 / The proposed integration

Give the existing owner an executable handoff.

Add an opt-in changeset backend at spec_editor. The current owner already settles behavior and supplies source context. It can compile a coherent batch directly, without adding another planning model.

  1. 01 / Prepare

    Step + current source

    Compile when the step runs, after prerequisites land. Preserve the prepared acceptance requirements.

  2. 02 / Extend

    Changeset backend

    Use the managed writer lease, staged workspace and scheduler. Keep the ordinary editor available.

  3. 03 / Assess

    Batch checks + repair

    Owner runs required focused gates. Test-first steps still observe the intended failure before implementation.

  4. 04 / Complete

    Commit + review

    Retain completion receipts, independent step review and coordinator acceptance.

Engineering still required

  • Connect leases, path fences, cancellation and managed receipts.
  • Scope snapshots and preserve dirty files; route unsupported inputs to the existing editor.
  • Detect stale source and define interrupted-publication recovery.
  • Adapt batch review to existing responsibilities and make repair/fallback explicit.

The next comparison

Measure real prepared steps against today’s managed owner/editor process, which already batches and parallelizes some work. Count time through verification and independent review repairs, acceptance, calls, tokens and fallback rate.

Start with capable planning and deterministic edits. Evaluate cheaper routing separately. The measured 24% reduction is not an estimate for the entire spec workflow.
