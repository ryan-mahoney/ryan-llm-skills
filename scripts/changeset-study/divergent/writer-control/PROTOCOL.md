## Original prospective protocol

The text below records the preparation design registered before live execution.
Its original unmeasured status is historical; frozen copies remain unchanged.

This is an unmeasured, separate research control, not a new production route. Require
terminal run 18 to complete application across the original calibration, handoff and
extraction cases. Select no subset. The current research goal, models and shared $50 budget authorize the comparison.
Root coordinates concrete live execution after audit and a freeze, using the qualified
candidate and frozen repeat; no additional user approval is required. Retain the donor manifest, code, SDK,
dependency, task, plan, brief and result identities before any inference.

Freeze the control harness separately; execute the donor's exact frozen worker and
backend without overlays. Preserve initial source, complete owner brief, raw plan,
dispatched partitions, source selections, explicit dependencies, concurrency four,
one local retry, source/assignment bounds, requested output/call/deadline limits and
outer checks. Set optimization none, writer Sol6.1 low, recovery selector null.
No fresh owner, Sol query, review or behavioral repair occurs. Dependent excerpts
come from each arm's own staged writes; later bytes can legitimately differ.

There are two potential policy differences despite identical execution code:

- The known pinned Sol subscription adapter omits requested maxTokens from its
  serialized provider request. DeepSeek uses max_tokens. Record the exact adapter
  hash and the missing equal enforced ceiling; unknown adapter hashes are unverified.
  Do not describe these as identical provider-enforced output limits.
- With recovery selector null, the frozen backend's legacy same-selector retry may
  catch nonterminal transport/model errors. Configured DeepSeek off-to-low recovery
  only retries decoded-format, edit-application or syntax rejection. Keep exact code;
  an observed control retry after a transport/model failure invalidates comparison
  eligibility. Retain its incurred charges and outcome. A control with only local
  application retries can describe matched observed writing conditions with these
  potential policy differences explicit, rather than identical enforced policies.

The dedicated auditor requires only the authorized Sol selector, editor stage,
matching request/receipt/response identities, dispatched operation IDs, attempts0/1,
matching assignment fields and unchanged retry input except local diagnostics. It
replays source selection and edits from frozen initial source and checks candidate
hash, protected paths, call/token accounting and recorded downstream checks. Candidate
checks and terminal acceptance are outcomes, not feedback to another model. No
independent review or full spec conformance is inferred from those gates.

Use the existing canonical donor ledger, schema1/limit50, before preparation and each
cell. Do not hash mutable ledger contents, reset it, reduce conservative Sol output
reservations, or serialize writers to make reservations fit. Preparation records the
four-call estimate using the largest retained donor writer packet, provider tier
maxima and max(model.maxTokens, model.contextWindow, requested output tokens). Stop
before a case if four such reservations no longer fit. Unseen staged packets can
still differ; the unchanged Client reservation remains authoritative.

The read-only readiness check during prototype construction observed Sol capacity
500,000 tokens, tier maxima $5 input/$15 output per million, $9.375 output-only per
reservation, and $38.563375 for four calls at the largest retained packet (42,535
Client input-bound bytes). Ledger headroom then was $46.805904772. These are a dated
snapshot and retained-packet estimate, not a guarantee of future budget availability
or an upper bound on unobserved staged inputs.
