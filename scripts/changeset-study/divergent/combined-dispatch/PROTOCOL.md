# Matched combined dispatch comparison

This research comparison reuses the exact run18 smaller-regions raw Sol plans, original task source, limits and implementation briefs for all three original cases. It makes no new owner, query or Sol calls. There is one observation per arm and case: calibration runs baseline then combined, handoff runs combined then baseline, and extraction runs baseline then combined. All workers run sequentially.

The baseline uses the current focused JSON writer, optimization none, native DeepSeek Flash with thinking disabled, and its existing same-selector local retry. The combined arm uses the opt-in optimized-v4a profile: bounded contextual preprocessing with one Jev batch, deterministic grouping/context selection, then the same DeepSeek writer producing V4A with at most one local JSON fallback. No model receives downstream checks or private acceptance feedback. The combined treatment changes grouping, context and format together; this does not isolate the effect of V4A.

Both arms retain the donor's 20-minute implementation allowance, 96-call limit, 32,000 requested output tokens, five-minute call and grading allowances, and existing command limits. Each original operation has at most two writer attempts. The 26 original operations therefore permit at most 104 writer requests across both arms, plus at most three Jev reservations. Grouping cannot increase this ceiling. The baseline's legacy transport-retry eligibility differs from the combined local-only fallback; an observed transport-triggered baseline retry must remain visible and cannot qualify as matched local recovery.

The canonical existing $50 ledger is shared and never reset. A frozen worker guard additionally requires this campaign's charged cost plus held reservations plus the next proposed reservation to fit $2. It does not reduce output, context or call limits to make requests fit. Every reservation is registered before network submission. A registry write failure preserves the canonical hold, records its identity separately, stops before submission, and invalidates the comparison. Missing settlement evidence, unknown exposure, unauthorized routing, changed pins or schema failures stop later trials. All incurred costs and failures remain retained.

Using the largest retained run18 writer packet, the unchanged reservation formula estimates $0.063950625 per request and $6.650865 for all 104 allowed writer requests, before Jev. These are conservative retained-packet estimates, not bounds on future staged source. The actual $2 exposure guard is authoritative and can stop an otherwise valid trial; such a stop is reported rather than treated as a model failure or silently raising the cap. The coordinator reviews this preflight before releasing inference.

Preparation freezes the current committed backend, Node identity, exact parser, full SDK 1.2.0 dependency tree, original read-only dependency mount and the complete Jev node_modules tree. Both arms use these same snapshots. The worker pins SDK and Jev imports internally and verifies native DeepSeek model metadata. Normal credentials remain outside the snapshot. Saved artifact paths are relative to the output root; only execution-local source and canonical-ledger paths are absolute.

Run `runner.mjs prepare --source <run18> --output <new-adjacent-output> --ledger <existing-ledger> --sdk <sdk-root> --parser <acorn-module> --jev <pi-typesafe-entry>`, then use the frozen runner's `verify --output <output>` and, after reviewed committed freeze and coordinator release, `run --output <output>`. Preparation performs no inference. Each trial retains its complete job, source identities, requests, responses, receipts, routing artifacts, dispatched plan, writer attempts, candidate, visible checks, private grading and audit.

Reporting separates application completion, visible regression/candidate checks, hidden acceptance and path/protected-file audited delivery. Writing execution wall, optimizer wall and contained Jev routing time are separate; routing must not be added twice to preprocessing. Provider elapsed sums are a different latency measure. DeepSeek primary/fallback calls, usage and receipt charges remain separate from Jev request counters, input-estimated cost and unknown exposure. The arithmetic combined charge is not described as an independently verified invoice. Inherited planning cost is excluded from the matched writing denominator and may only be shown as a clearly separate allocation. Six single observations cannot establish a speed or reliability winner or generalize beyond these exposed cases.

The first execution stopped after the calibration pair because its auditor treated JSON object key order as identity in a source-map hash. The observer-only correction is separately frozen for an explicit four-trial continuation. `resume.mjs prepare --original <campaign> --output <campaign/resume-01>` pins the stopped report, both original observation inventories, reservation-registry prefix and corrected audit harness. Its `verify` and `run` commands use that output. Both retained observations must pass the corrected read-only audit before any new call. The remaining four trials use the original frozen workers, backend, SDK, Jev tree, source, plans, briefs, limits and cumulative $2 guard. Original stopped reports and audit files are preserved; continuation audits and the six-observation report are separate. No calibration repetition or new planning is permitted.
